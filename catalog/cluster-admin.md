#### [alkir-rahc (Alkir-RAHC)](https://github.com/DigiLabsru/alkir-rahc)

★ 41 · обновлён 2025-07-28 · лицензия MIT · найдено при доборе пропусков, скептик не проверял

Java-приложение (Spring) на официальной java-библиотеке 1С для RAS: REST и JSON-RPC API (OpenAPI/Swagger UI) для сеансов, соединений, их отключения, лицензий, состояния кластера и рабочих процессов (rphost/rmngr). Запуск одним docker run, токен авторизации.

- **Работает:** Java + Docker (любая ОС, включая macOS); подключается к RAS по сети
- **Нужно:** RAS на сервере 1С, Docker, сетевой доступ до RAS; лучше задать AUTH_TOKEN
- **Доступ к данным:** live-data-read
- **Риски:** API умеет отключать сеансы/соединения (запись), без токена открыт всем; не выставлять наружу. Данные сеансов включают имена пользователей. В примере указан образ alkir/rahc:20211130 — свежесть образа не проверялась, лучше собирать из исходников.
- **Почему такая оценка:** Рабочая готовая HTTP-обёртка над RAS с OpenAPI-спекой, которую удобно скормить агенту; наиболее живая из REST-вариантов (41 звезда, MIT, push 2025-07). Не core: узкий круг задач (администрирование баз заявлено «в планах»), образ в Docker Hub с датой 2021-11 в примере, обновления редкие.
- **Версия на дату проверки:** `99ac9e7a5501` (2025-07-28)

#### [alkir-web-rac](https://github.com/DigiLabsru/alkir-web-rac)

★ 14 · обновлён 2025-08-03 · лицензия MIT · найдено при доборе пропусков, скептик не проверял

Stateless HTTP API к RAS на java-библиотеках 1С (не обёртка над rac): заявлена поддержка всех команд RAC (чтение, создание, изменение), метрики Prometheus по сеансам и рабочим процессам; запуск в Docker с лимитом памяти.

- **Работает:** Java + Docker (macOS ок); подключается к RAS по сети
- **Нужно:** RAS на сервере, Docker, сетевой доступ; пароли администратора кластера передаются в теле каждого запроса
- **Доступ к данным:** live-data-read
- **Риски:** Поддерживает мутирующие команды (создание/изменение объектов) без отдельного read-only режима; пароли кластера идут в JSON запросов — только по доверенной сети/TLS; сервис без встроенной авторизации по README — не выставлять наружу.
- **Почему такая оценка:** Покрывает полный набор команд RAC по HTTP — нужно, когда на серверах заказчиков надо смотреть сеансы, блокировки, соединения без RDP. Ниже alkir-rahc по зрелости: 14 звёзд, последний push 2025-08, в README указаны «известные проблемы» (утечки памяти в Java, нужен -m лимит), нет OpenAPI/токена в описанном виде.
- **Версия на дату проверки:** `42b8af55a3ce` (2025-06-10)

#### [python-rac (pyrac) — прямой клиент RAS: CLI, веб-консоль, MCP](https://gitlab.com/platform42/python-rac)

★ 0 · обновлён 2026-10-29 · лицензия MIT · найдено при доборе пропусков, скептик не проверял

Python-клиент, говорящий с RAS по TCP напрямую, без rac.exe: библиотека, CLI (pyrac), веб-консоль (pyrac-web, PWA, Docker), настольная консоль и MCP-сервер pyrac-mcp. Читает кластеры, серверы, процессы, базы, сеансы, соединения, блокировки; MCP по умолчанию только чтение, изменения включаются флагами --allow-*; в веб-консоли роли Администратор/Оператор/Наблюдатель и режим --read-only.

- **Работает:** Python 3.11+ (macOS/Linux/Windows), RAS 10.0–22.0 (платформы 8.3.x–8.5.4); веб-консоль в Docker; exe для Windows в релизах
- **Нужно:** Запущенный RAS на сервере 1С (порт 1545) и сетевой доступ до него (VPN/SSH-туннель к серверу заказчика); pip install python-rac[mcp]
- **Доступ к данным:** live-data-read
- **Риски:** Через CLI pyrac изменения применяются сразу без подтверждений (в README сказано явно). Флаги --allow-* для MCP не включать на рабочих базах. Сеансы/соединения содержат имена пользователей и хосты. Лицензия MIT указана в README и файле LICENSE (GitLab API license=null). Протокол RAS реверсирован самим автором, а не взят из офиц. Java-библиотеки 1С: при выходе новых версий платформы возможны расхождения.
- **Почему такая оценка:** Единственный найденный вариант, который работает на macOS без платформы 1С (чистый Python), закрывает и веб-админку, и агентный MCP, и безопасен по умолчанию (read-only). Не core: проект молодой (создан 2024, v1.5.2 от 2026-10-29), на GitLab, 0 звёзд, сообщества нет, история стабильности неизвестна; основная ветка называется beta.
