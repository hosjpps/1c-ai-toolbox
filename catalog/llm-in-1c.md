★ 108 · обновлён 2026-11-06 · лицензия MIT · проверено скептиком

Расширение 1С (CFE, платформа 8.3.27+): коннектор к разным LLM (облачные и локальные Ollama/LM Studio), агентская петля с инструментами, RAG на Qdrant, MCP-сервер к базе (HTTP, JSON-RPC, read-only запросы), мониторинг ошибок с ИИ-диагнозом, маскирование ПДн перед отправкой модели.

- **Работает:** 1С:Предприятие 8.3.27+ как расширение (Windows/Linux-серверы 1С); RAG — внешний Qdrant; на macOS запускается только через удалённую платформу
- **Нужно:** Платформа 8.3.27+, БСП, ключи API провайдера или локальная Ollama/LM Studio; для RAG — Qdrant; для ПДн на именах — Python-сервис ner-shim

- **Риски:** Данные базы уходят облачной модели (ФИО/ИНН/СНИЛС/телефон/почта маскируются, одиночные фамилии, адреса и организации без сервиса Natasha не ловятся). MCP-сервер идёт мимо маскирования: внешний агент читает данные по правам MCP-пользователя, SECURITY.md требует отдельную роль без полных прав и сильный пароль, публиковать только по HTTPS. Подписочные адаптеры ChatGPT/GLM (личные коды) могут нарушать условия провайдеров. Ставить только на копию базы.
- **Почему такая оценка:** Самый зрелый открытый вариант «LLM внутри 1С» (v1.9.2, MIT, 1147 тестов по README, ежедневные пуши, отдельные репо с гайдом и тестами). Нужен не в каждом проекте, а когда заказчик хочет ИИ в самой базе; маскирование ПДн по умолчанию — редкий плюс для 152-ФЗ.
- **Проверка:** gh api: 108★, push 2026-11-06, MIT, не archived — совпало. README и VERIFICATION.json: версия 1.9.2, 1147/1147 тестов (EDT), исходники в репо (src, DT-INF, build-info), CFE 8.3.27+. Остальное подтвердил, но не core: нужен только когда заказчик хочет ИИ внутри базы.

#### [BSL Atlas](https://github.com/Arman-Kudaibergenov/bsl-atlas)

MCP-сервер в Docker: индексирует XML/BSL-выгрузку конфигурации или расширения, даёт структурный поиск (процедуры, модули, метаданные, граф вызовов) в режиме fast без внешних API и семантический в режиме full.

- **Работает:** Docker (Linux-контейнер; Mac Apple Silicon — образ не проверял), Python внутри
- **Нужно:** Выгрузка конфигурации в файлы, bind mount каталога в /data/source; для full — embedding backend/ключ
- **Доступ к данным:** code-metadata
- **Риски:** В режиме full код уходит embedding-провайдеру. AGPL-3.0 — обязательства при выдаче сервиса третьим лицам. MCP слушает localhost:8000 без авторизации — не пробрасывать наружу. Образ с Docker Hub собран автором, содержимое не проверено.
- **Почему такая оценка:** Режим fast работает без внешних embedding API, т.е. код не уходит наружу; Docker запускается на Mac. Хорошее быстрое решение «поиск по выгрузке», дополняет rlm-tools-bsl. AGPL — для личного использования без дистрибуции нормально.
- **Проверка:** gh api: 79★, push 2026-07-26, AGPL-3.0, не archived — совпало. README: режимы fast/full, SQLite/FTS, bind mount SOURCE_PATH.
