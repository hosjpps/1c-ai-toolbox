# AGENTS.md — как агенту пользоваться коробкой

Ты в проекте на 1С, и пользователь сказал взять инструменты из коробки (`github.com/hosjpps/1c-ai-toolbox`, локально обычно `~/git/1c-ai-toolbox`). Порядок такой.

## 1. Выяснить проект

Сначала из файлов и документации проекта, вопросы — только о том, чего там нет:

- **Конфигурация и версия:** типовая (УТ 11, БП 3, ERP, КА) на поддержке, своя, расширение к типовой. Версия платформы (8.3.x) — от неё зависит, что заработает (Unica, например, только 8.3.27+).
- **Где исходники:** XML-выгрузка Конфигуратора, проект EDT, или пока нигде. Если нигде — первый шаг проекта [recipes/dump-config.md](recipes/dump-config.md), без него почти весь каталог бесполезен.
- **Где платформа:** у пользователя Mac (Apple Silicon), платформа 1С обычно на удалённом Windows-ПК или сервере заказчика. См. [recipes/macos.md](recipes/macos.md).
- **Какие базы есть:** рабочая (только чтение) и тестовая копия. Без тестовой копии — никаких инструментов, которые пишут в базу.
- **Что за работа:** доработка типовой, обмен с сайтом или другой системой, своя конфигурация с CI, разбор производительности, ИИ внутри 1С.

## 2. Подобрать набор

Начать с базового набора из [README.md](README.md), потом добрать по профилю. Брать 3–7 инструментов, не всё подряд: каждый лишний скилл и MCP занимает контекст и путает выбор.

| Профиль | Что смотреть в каталоге |
|---|---|
| Доработка типовой через расширение | `cc-1c-skills` (`cfe-*`), BSL LS, поиск по большой конфигурации (`rlm-tools-bsl` / `code-index-mcp`), знания по БСП ([knowledge](catalog/knowledge.md): `ssl_3_1`, `v8std`), правила [rules/bsl.md](rules/bsl.md) |
| Обмен 1С с сайтом или внешней системой | [integration](catalog/integration.md): HTTP-клиент `Connector`, `OpenIntegrations`, CommerceML от 1С, `swagger-1c` для HTTP-сервисов |
| Своя конфигурация, git и CI | [build-ci-vcs](catalog/build-ci-vcs.md): OneScript, `vanessa-runner`, `gitsync`, `precommit4onec`, `onec-docker`; [testing](catalog/testing.md): YAxUnit, Vanessa Automation; [edt](catalog/edt.md), если проект в EDT |
| Разбор медленной базы, администрирование | [techlog](catalog/techlog.md), [monitoring](catalog/monitoring.md), [cluster-admin](catalog/cluster-admin.md), [dev-consoles](catalog/dev-consoles.md) |
| Живые данные базы для агента | [mcp](catalog/mcp.md) — только после [SECURITY.md](SECURITY.md): метаданные можно, данные — через обезличивание и только на тестовой копии |
| ИИ-помощник внутри 1С | [llm-in-1c](catalog/llm-in-1c.md) |

Из одной роли брать один инструмент: `cc-1c-skills`, `Unica` и `Desko77/claude-code-skills-1c` пересекаются — выбрать один движок работы с XML, остальные максимум как справочник.

## 3. Согласовать и поставить

- Показать пользователю выбранный набор: что, зачем, что требует, какие риски из карточки. Ставить после «да».
- Версию брать из `data/tools.lock.json` или новее, но перед установкой посмотреть, что поменялось.
- Перед установкой прочитать код хуков, установщиков и всего, что качает бинарники (см. [SECURITY.md](SECURITY.md)).
- Скиллы и правила — в сам проект (`.claude/skills`, `AGENTS.md`/`CLAUDE.md` проекта), а не глобально: в разных проектах разные наборы.
- Нужные пункты [rules/bsl.md](rules/bsl.md) перенести в правила проекта и дописать местные (стиль программиста заказчика, префиксы, пометки).

## 4. Записать

В документацию проекта: какой набор выбран, каких версий, почему не взяли альтернативы. Если инструмент оказался плохим или хорошим на практике — поправить его карточку в `data/catalog.json` коробки и пересобрать `python3 scripts/build_catalog.py`: коробка учится на проектах.
