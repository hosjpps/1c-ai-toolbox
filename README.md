# 1c-ai-toolbox

Личная коробка инструментов для разработки на 1С:Предприятие 8.3 вместе с ИИ-агентами (Claude Code, Codex, Cursor). Отсюда в каждый новый 1С-проект подтягивается то, что ему нужно, — без повторного поиска по GitHub.

Каталог собран 07.11.2026: 9 поисковых агентов по категориям, по скептику-проверяющему на категорию, критик полноты и добор пропусков. Все 242 ссылки на GitHub дополнительно сверены `gh api` (существует, звёзды, дата, лицензия, архив). Ничего из каталога при отборе не запускалось — оценки по коду и документации.

## Как пользоваться

- **Агент в новом 1С-проекте** — читает [AGENTS.md](AGENTS.md): там порядок подбора набора под проект.
- **Человек** — начинает со сводки [catalog/INDEX.md](catalog/INDEX.md), дальше в файл нужной категории.
- **Правила для кода BSL**, которые переносятся в проект, — [rules/bsl.md](rules/bsl.md).
- **Безопасность** (ПДн, рабочие базы, чужие хуки и бинарники) — [SECURITY.md](SECURITY.md). Читать до установки чего-либо.

## Базовый набор

Подходит почти любому проекту, где исходники конфигурации или расширения лежат в файлах.

| Что | Зачем | На Mac |
|---|---|---|
| [cc-1c-skills](https://github.com/Nikolay-Shirokov/cc-1c-skills) | Скиллы для XML-выгрузки: метаданные, формы, СКД, роли, расширения (заимствование, перехватчики), валидация | Да, Python-порт; команды `db-*` и `web-*` — только Windows с платформой |
| [BSL Language Server](https://github.com/1c-syntax/bsl-language-server) + [claude-code-bsl-lsp](https://github.com/1c-syntax/claude-code-bsl-lsp) | Диагностики и навигация по BSL после каждой правки агента | Да |
| [vsc-language-1c-bsl](https://github.com/1c-syntax/vsc-language-1c-bsl) | Чтение и правка BSL глазами в VS Code / Cursor | Да |
| [rlm-tools-bsl](https://github.com/Dach-Coin/rlm-tools-bsl) или [code-index-mcp](https://github.com/Regsorm/code-index-mcp) | Поиск по большой конфигурации (УТ, ERP) без чтения файлов целиком | Проверить на месте |
| [v8unpack](https://github.com/saby-integration/v8unpack) | Распаковка cf/cfe/epf без платформы | Да |
| [OneScript](https://github.com/EvilBeaver/OneScript) + [opm](https://github.com/oscript-library/opm) | Скрипты автоматизации на языке 1С, основа CI-инструментов | Да |
| [YAxUnit](https://github.com/bia-technologies/yaxunit) | Юнит-тесты, ставится расширением в тестовую базу | Тесты идут в базе |
| [Инструменты разработчика (tools_ui_1c)](https://github.com/cpr1c/tools_ui_1c), [ИР (RDT1C)](https://github.com/tormozit/RDT1C) | Консоли запросов, кода, СКД внутри базы — для ручной проверки | Нет, это обработки в базе |

Остальное — по профилю проекта, см. [AGENTS.md](AGENTS.md) и [catalog/INDEX.md](catalog/INDEX.md).

## Что внутри

| Путь | Что |
|---|---|
| `catalog/` | Карточки по 14 категориям: что делает, на чём работает, что нужно, доступ к данным, риски, почему такая оценка. Генерируется |
| `catalog/gaps.md` | Что критик нашёл, но в каталог не вошло, и отсеянное |
| `data/catalog.json` | Исходные данные каталога (оценки, тексты) |
| `data/github.json` | Факты GitHub на дату проверки |
| `data/tools.lock.json` | Коммиты отобранных инструментов на дату проверки — от чего отталкиваться при установке |
| `rules/bsl.md` | Проверенные правила для кода 1С |
| `recipes/` | Выгрузка конфигурации в файлы, работа с Mac |
| `research/` | Скрипт исследования (workflow для Claude Code) и сырые логи прогона |
| `scripts/build_catalog.py` | Сборка `catalog/` из `data/`, `--refresh` обновляет факты GitHub |

## Обновление

```bash
python3 scripts/build_catalog.py --refresh   # звёзды, даты, лицензии, архив — через gh api
```

Раз в несколько месяцев имеет смысл новый прогон исследования (`research/workflow.js`): экосистема ИИ-инструментов для 1С меняется каждый месяц, половине каталога меньше года.

Оценки — мнение на дату проверки, а не гарантия. Перед установкой в проект — прочитать код того, что ставится, особенно хуки и скачиваемые бинарники.
